Reading rule messages
  • Messages from a rule check start with Value error, ; the frontend removes that prefix before showing it.
  • A wrong option gives 'x' is not one of: a, b, c.
  • Two errors appear on most write endpoints: facility is required (400) and Set the unit code for this facility first (400).

Registration flow map

Which call happens at each step of the front-desk screens.

  1. Sign in POST /api/v1/auth/login/ → GET /api/v1/users/getcurrentuser/
  2. Search the patient by phone or name GET /api/v1/patient/?phone_number=, by UHID GET /api/care_emergency/patients/search/?uhid=, by ABHA POST /api/v1/patient/search/; numbers and last visit POST /api/care_emergency/patients/summary/
  3. No match → Add Patient. Address from PIN GET /api/care_emergency/pincode/<pin>/
  4. Upload documents (passport, visa, payer card) POST /api/care_emergency/documents/ — each returns an id
  5. Save Domestic / International / IVF POST /api/care_emergency/registration/ with the document ids; New Born POST /api/care_emergency/newborn/register/
  6. Photo and signed consent POST /api/v1/files/upload-file/
  7. Emergency GET /api/care_emergency/desk/ → POST /api/care_emergency/register/; later POST /api/care_emergency/patients/<id>/convert/
  8. Phone booking POST /api/care_emergency/quick-registration/; patient fills /quick-registration/form/<token>/
  9. Book appointment POST /api/care_emergency/appointments/

Emergency

POST/api/care_emergency/register/

Quick emergency registration. Creates the patient (with the desk phone), an emergency encounter and the emergency record in one step.

Who
Users who can create encounters in the facility, and create patients.
Send

  • patient: name, gender, date_of_birth or age (0–120)

  • chief_complaint (e.g. Chest pain, Fall), mode_of_arrival (e.g. Walked in, 108 ambulance)
  • is_medico_legal, mlc_nature, police_station, brought_by {name, phone_number, relationship}
Returns
{patient, encounter, emergency}; emergency includes mlc_number (MLC-2026-0001) and the UNK number for unknown patients.
Errors
400Select the chief complaint · Select the MLC nature · Enter the police station informed
400Enter an estimated age between 0 and 120 · Enter who brought the patient in or their phone number
400Set the emergency desk number for this facility first · Set the unit code for this facility first
403You do not have permission to create encounter · Cannot Create Patient
404Unknown facility

Desk registration

POST/api/care_emergency/registration/Domestic · International · IVF

Full front-desk registration. Creates the patient, issues the UHID (or a PRE number), saves all desk details, allergies and attached documents. For IVF it also registers the partner.

Who
Users who can create patients. "No phone" registrations also need access to the facility.
Send
  • facility, pre_registration (true → PRE number), documents (up to 20 staged document ids), couple (IVF only)
  • patient: name, gender, phone_number, date_of_birth or age, address, pincode, geo_organization
  • registration, required groups:
    • Identity — registration_type (DOM, TPA, CORP, STAFF, GOVT, INT, NRI, CPL), title, first_name, preferred_language
    • Contact — mobile_owner; optional WhatsApp, alternate mobile, address, next of kin
    • ID — nationality_category (Indian resident, NRI, OCI-PIO, Foreign, Refugee); optional ID type + last 4, ABHA
    • International — nationality (country of origin), passport_number, visa_type, visa_expiry, address_in_india
    • Safety — allergy_status (nka, has, unable), allergies, VIP flags
    • Payer — payer_type (Self, Corporate, Insurance/TPA, Govt scheme, Staff, International) + its fields
    • Source — arrival_source (e.g. Walk-in, Outside doctor)
    • Consent — consent_given_by, consent_method, consent_language, general_consent, data_processing_consent, tariff_consent; international_tariff_consent for INT/NRI
Returns
{patient, registration}; the patient's instance_identifiers carry the UHID.
Errors — names, contact & consent

Billing rules

No billing endpoints in the plug

The plug adds checks to Care's own charge item, invoice and payment APIs (only in facilities with a unit code). Numbers look like INV/LN/26/00001 (also CN, RCT, ADV, RFD). Errors you may see from those Care APIs:

  • Quantity must be a whole number from 1 to 20 · Amounts are whole rupees, up to 7 digits
  • A refund needs its cause · A refund needs a reason · A patient-caused refund above ₹500 needs a supervisor
  • An advance needs its purpose · Complete the patient's registration first

Points to review

Found while reading the code. Not bugs in the screens, but worth a decision.

  • Desk registration facility check: POST /registration/ checks facility access only for "No phone" patients; otherwise it relies on Care's general "can create patients".
  • Convert: POST /patients/<id>/convert/ has no plug-side permission check; it relies on Care's patient update check.
  • Login errors are 403: Care returns 403 (not 401) for wrong passwords and expired tokens. Clients must read code: "token_not_valid" to know when to refresh.
  • File storage: document uploads need the S3 storage (Silo) settings on the backend, or they fail with "Invalid endpoint".

No endpoint matches that search.
